## Verdict

The foundation is sound.

- Every documented performance and lifecycle invariant is correctly implemented (see "Verified as correct" below). The audits confirmed the invariants, they did not find them violated.
- Opening a maliciously crafted file is safe. The entire offline parser surface (`.bbl`/`.bfl`/`.airframe`/`.airframepreset`) is well hardened: no memory-safety, integer-overflow, allocation, recursion, `Data`-slice, force-unwrap, or quadratic-parsing bug reachable from file content.
- No network, analytics, or telemetry code exists anywhere (`App/` and `Packages/*/Sources/`): no `URLSession`, `URLRequest`, `NWConnection`, `CFNetwork`. Sockets are raw link-local only (no DNS).

All actionable defects are concentrated in four areas: the live SpeedyBee/BLE device path, the table-cache write path, close-time edge cases, and formatter allocations on hot render paths.

## Priority 1 — do first

### S1 — Security (high): trap/overflow on attacker-declared varint length
- **Where:** `Packages/FlightController/Sources/FlightController/SpeedyBeeControlProtocol.swift:132`
- **What:** `let end = start + Int(decoded.value)` runs before the bounds check on line 133; `decodeVarint` (lines 64-80) puts no ceiling on the value. `Int(decoded.value)` traps for values > `Int.max`; `start + Int(...)` can overflow `Int`. Both happen before any bounds validation.
- **Runtime:** A ~10-byte frame from a hostile or spoofed BLE peripheral (service `0000ABF0` or name `SBADAPTER3_*`) crashes the app pre-authentication. Identical reach over WiFi from a hostile AP (`SpeedyBeeWiFiClient.swift:462`).
- **Fix direction:** bound the varint (reject `shift > 63`), use `Int(exactly:)` / `addingReportingOverflow`, and check bounds before slicing.
- **Priority rationale:** the only finding reachable pre-auth from a single short frame. Treat as first.

### C1 — Cache (high): fire-and-forget per-chunk writes + write amplification
- **Where:** `App/Airframe/App/DocumentHome/Content/Table/MainFrameChunkCache.swift:71-83` (writes), `:69-84` (re-write), `:166` (`shutdown()` cancels only `inFlight`/`prefetches`).
- **What:** `load()` spawns one untracked `Task(priority: .utility)` per returned chunk to persist it; the tasks are registered nowhere, so they survive `shutdown()` and document close, each retaining a full decoded `ReaderMainFrameChunk`. The outer `load` persists the entire returned array including chunks already in RAM or just restored from disk, so every table window move rewrites every visible chunk (envelope encode + two SHA256 passes + atomic write + SQL upsert) even on a 100% cache hit.
- **Runtime:** during scrubbing/playback the window recenters repeatedly, spawning write bursts that serialize through the global `DerivedDataCache` actor and compete with playback; on close, hundreds of MB of chunk payloads can stay alive. Directly violates the coalescing invariant (invariant 3 below).
- **Fix direction:** adopt the `GraphPreparedSeriesCache` pattern (per-log coalesced/debounced write task stored in the actor, cancelled in `shutdown()`, suspended during playback); persist only chunks decoded in this call (`loadedByOrdinal` minus disk-restored), or track a dirty flag per key.

## Priority 2 — medium

### Stability
- **Re-entrant close double-calls `super.close()` and skips persistence** — `App/Airframe/App/WorkspaceDocument/AirframeNSDocument.swift:196-201, 285`. A second `close()` while `isFlushingBeforeClose == true` (termination sweep, programmatic close) hits the else branch and calls `super.close()` immediately, detaching before flush/maintenance finish; the still-running task then calls `super.close()` a second time. Fix: record a re-requested close in that branch and return without `super.close()`; let the single in-flight task own the one `super.close()`.
- **Vetoed close leaves a zombie document** — `AirframeNSDocument.swift:204` calls `workspaceController.processingActivityCounter?.shutdown()` before the flush; `ProcessingActivityCounter.shutdown()` is permanent (`App/Airframe/App/ProcessingActivityCounter.swift:105-121`). If the flush fails and close is vetoed (window stays open), every later `compute`/`backgroundTask` cancels instantly, so graph/scan/spectrum work silently dies and `duplicate(_:)` fails. Fix: move the counter shutdown into `finishClose()`, or add a revive path on veto.
- **Pending debounced mutations lost at Cmd-Q (macOS)** — genuine mutations persist via a 350 ms / 1 s debounce (`AirframeWorkspaceController.swift:51-52, 321-339`), but `updateChangeCount` suppresses editor changes (`AirframeNSDocument.swift:183-194`) so AppKit sees zero unsaved documents and terminates without calling `NSDocument.close()`; there is no `applicationShouldTerminate` flush. A rename/tag/report within ~350 ms–1 s of quit is silently dropped. Fix: `applicationShouldTerminate` returning `.terminateLater`, flush every open workspace controller, then `reply(toApplicationShouldTerminate:)`.
- **iOS close swallows maintenance/flush errors and omits the logging contract** — `App/Airframe/App/WorkspaceDocument/AirframeUIDocument.swift:146-148` uses `try? await persistence.prepareForClose()`; a durable-flush error escaping it is discarded without a log, and per invariant 5 a flush failure should veto. iOS also emits no start/flush-completed/maintenance-completed close logs. Fix: mirror the macOS structure (treat a throwing flush as a veto or at minimum log `diagnosticDescription`; add the log lines).

### Security (live device path only)
- **Unbounded BLE control buffer (memory DoS)** — `SpeedyBeeControlChannel.swift:169-191`. `handle(.bytes)` appends every notification with no cap and `deliverBufferedFrame` returns early when `frameWaiter == nil`, so a peripheral streaming notifications between exchanges grows `buffer` until OOM. Add `maximumBufferBytes`.
- **Download loop has no overall deadline and is uncancellable** — `SpeedyBeeWiFiClient.swift:328-398`. `lastDatagramAt` resets before validation; bad-CRC/zero-length datagrams keep `silence < burstSilenceBudget` forever so the reburst cap never trips; no `Task.checkCancellation`, so `close()` cannot run. Add an overall deadline and cancellation checks; validate before resetting the silence timer.
- **Quadratic / non-terminating completion check and huge allocation from attacker file size** — `SpeedyBeeDataPacket.swift:103-113` (consumed at `SpeedyBeeWiFiClient.swift:328`) and `:169`. `isComplete`→`missingSequences` walks `0..<packetCount` per received datagram; `packetCount` derives from the STAT reply (up to `UInt32.max`). `seq` is `UInt16`, so `packetCount > 65_536` can never complete; `reserveCapacity(packetCount * dataPerPacket)` can request ~4.3 GB. Clamp declared size, cap `packetCount`, reject `> 65_536`.
- **`UInt32` overflow in dataflash download loop** — `Packages/FlightController/Sources/FlightController/BetaflightClient.swift:1227-1261` (esp. `address += UInt32(bytes.count)`, line 1259). `requestedLength` is not clamped to `remaining` under compression, and an uncompressed reply is not clamped to `maximumOutputLength` (clamp only on the compressed branch, line 1337). A device reporting `usedBytes = totalBytes = 0xFFFFFFFF` (only `used <= total` checked, `BetaflightParsing.swift:111`) drives `address` past `UInt32.max` → trap, after writing ~4 GB. Sanity-check reported size in `validateDownload`.
- **Unvalidated peripheral-chosen SSID** — `SpeedyBeeWiFiInfo.swift:19-27` → `SpeedyBeeAdapter3WiFiImporter.swift:86,186` → `WiFiNetworkJoining.swift:94-159`. First NUL-delimited run taken as SSID via `decodeLatin1`, no length/charset bound (control chars, RTL overrides pass), flowing into `CWInterface.associate` / `NEHotspotConfiguration(ssid:)` and user-facing text; nothing authenticates the peer at `192.168.1.1` (the "session token" `3197` is a fixed constant). Bound and sanitize the SSID.

### Cache
- **Orphaned entry files never reconciled** — `Packages/AirframeCache/.../DerivedDataCache.swift:80-85` writes the payload file before the catalog upsert (line 85); `reconcile()` (`:192-209`) only removes catalog rows with missing files, never files missing from the catalog. Real disk usage silently exceeds the enforced quota until "Clear" or OS purge. Fix: enumerate `entries/` during `reconcile()` and delete uncatalogued files, or upsert before writing and treat a missing file as a miss.
- **Heavy synchronous work on the single global cache actor** — `DerivedDataCache` is one process-global actor; `store` does full-payload copy + SHA256 + atomic write + SQLite synchronously, and `data(for:)` re-hashes the whole payload on every hit (`CacheFileEnvelope.swift:16-27, 44`). A large graph-bundle write blocks all other cache reads/writes. Fix: hash/encode off-actor, keep only catalog mutation on the actor; consider CRC32/xxHash or size+mtime validation; delta/per-entry storage for graph bundles.
- **O(n^2) eviction with unindexed LRU scans** — `DerivedDataCache.swift:245-250, 283`; no index on `accessed` (`:186`). Shrinking the quota (e.g. 10 GB → 100 MB) evicts thousands of entries at O(n) queries each, inside the actor. Fix: running in-memory total, index on `accessed`, batch-delete victims in one statement.
- **Bounded but post-close fire-and-forget writers** (lower than C1, same class) — step-response `StepResponseResultsState.swift:91, 190`; `Packages/AirframeUI/Sources/AirframeUI/AirframeDocumentModel.swift:171-173` (`Task.detached` capturing `decodedLog` + full scan); `OverviewContainer.swift:326, 528, 556`; `GraphCraftSection.swift:371-380`; `DocumentHomeView.swift:294-302, 309-317`. Route through a document-scoped write coordinator cancelled in `releaseDocumentCaches()`.

### Performance (SwiftUI)
- **`DurationFormatter` allocates a fresh `NumberFormatter` per call on hot paths** — `Packages/AirframeUnits/Sources/AirframeUnits/DurationFormatter.swift:115-123`. Hot callers: `TableRowView.timeText` (`Table/TableSurface.swift:593-596`, per visible row per render), `LogPlaybackTimestamp` (`Playback/LogPlaybackControls.swift:222-233`, every 100 ms tick), `LogTimeline` accessibility value (`Content/LogTimeline.swift:140`, 34 ms cadence during playback). Fix: cache `NumberFormatter` instances inside `DurationFormatter`, or precompute row time strings at `TableModel` build time (already cached in `TableModelCache`).
- **`LogDataView` rescans events every 100 ms tick during playback** — `App/Airframe/App/DocumentHome/Content/LogDataView.swift`. `presentationTimelinePosition` (`:552-555`) reads the observable `readoutPosition`, so the whole container body re-evaluates every 100 ms; `commandCapabilities` calls `interestingTimes(in:)` twice (`:676-706`), a full scan + `Set` build + sort, O(n log n) per tick for data immutable per (log, range). Fix: memoize by (logID, playbackTimelineRange) and answer `hasInterestingTime` with two binary searches; and/or split the capability computation into a leaf so `readoutPosition` invalidates only that leaf.

## Priority 3 — low / informational

- **Synchronous full-container read + SHA256 on the main thread at open** — `AirframeNSDocument.swift:114-127` (`canConcurrentlyReadDocuments` returns `false`), `AirframeUIDocument.swift:96-114`; `AirframeContainerCodec.open` verifies every blob (payloads up to 1 GiB). Beachball proportional to container size. Fix: allow concurrent reads or decode off-main behind the loading state.
- **Export staging on the boot volume can tear a cross-volume destination** — `App/Airframe/App/WorkspaceDocument/Container/AirframeContainerTransfer.swift:25-28` stages in `temporaryDirectory` (not the destination's item-replacement directory); fresh cross-volume destination falls back to a non-atomic `copyItem` inside the coordinator (`:57-61`). Fix: stage via `url(for: .itemReplacementDirectory, appropriateFor: destination)`.
- **Swallowed persistence errors** — `App/Airframe/App/DocumentView.swift:122, 125, 404` (`try?` on reference-log replace / state staging / conversion); genuine failures are indistinguishable from the expected read-only case and lost on close. Fix: log failures, distinguish `rawLogIsReadOnly` from real errors.
- **Invisible folder-open failure** — `ReadOnlyFileMenuPolicy.swift:368-373` only logs; every other open path presents the error. Fix: `presentError`.
- **Predictable-name diagnostics temp file** — `FlightControllerDiagnosticsPresentation.swift:39` writes the FC diagnostics report to a fixed filename directly in the shared temp dir (unlike every other temp write, which uses a UUID subdir); cleanup is best-effort. Sandbox 0600 limits exposure.
- **`0o644` widening on MSC import** — `MassStorageVolumeImporter.swift:87` sets imported logs to `0o644` where `0o600` would still clear the inherited FAT/exFAT flag.
- **Possibly-removable `network.server` entitlement** — `Airframe-macOS.entitlements:21-22`; the SpeedyBee UDP receive binds an ephemeral port for an app-initiated flow. Test removal.
- **`Task(priority:)` / wall-clock nits** — `TableScrollPositionCoordinator` uses `Date()` for suppression windows (`Table/TableSurface.swift:599-632`; prefer `ContinuousClock`); `PlaybackContent` rebuilds map content every 34 ms tick (`Map/MapContainer.swift:875-941`, inputs bounded, likely by design — equality-gate the polyline prefix on `prefixEndIndex` only if map playback jank appears).
- **Latent force-unwraps against project convention (not attacker-reachable)** — `AirframeContainerCodec.swift:53` `entry.mimeType!` (guarded by manifest validation), `FlightControllerDiagnostics.swift:93-95` `Dictionary(uniqueKeysWithValues:)` (use `uniquingKeysWith:`), `AirframeApp.swift:126` unsanitized `sourceName` into `appendingPathComponent` (DEBUG-only, do not copy into shipping code).

## Verified as correct (do not regress)

Performance/playback: 34 ms/100 ms cadence-gated readout channels with lazy exact-cursor fallback (`LogPlaybackController.swift`, `TableSurface.swift`, `GraphCraftSection.swift`); preindexed table row lookup + tiny window driver (`TableModel.swift`, `TableSurface.swift`); 34 ms map cursor leaf with equality-gated publication and immutable-value HUD instruments owning no timers/tasks/bindings (`MapInstruments.swift`, `AviationInstruments/*`); stable single MapKit annotation identity + fixed 208-pt host (`MapContainer.swift`); leaf-local render-only measurement drafts coalesced to ~120 Hz (`AnalysisRangeMeasurement.swift`); immutable Y-axis from the fixed 2,048-point source-bin-anchored envelope (`SpectrumModel.swift`, `StackedSpectrumSurfaceCanvas.swift`); source-bin-anchored frequency downsampling (`SpectrumSurfaceCanvas.swift`); native-List sidebar focus with no reclaim on `stateKey` change and hover restoring pinned highlights (`Sidebar.swift`, `LogDataView.swift`, `GraphHighlightState.swift`).

Stability/lifecycle: close as authoritative release boundary on macOS and iOS (`AirframeNSDocument.swift`, `AirframeUIDocument.swift`, `AirframeWorkspaceController.swift`, `AirframeDocumentModel.swift`); broker close boundary via weak pointer-personality `NSHashTable` with rejected late registrations and no document-retaining menu closures (`LogViewCommands.swift`); `fileModificationDate` refresh after custom writes; no AppKit autosave, suppressed editor change counts, File menu policy removing Save/Save As/Revert/Browse Versions (`ReadOnlyFileMenuPolicy.swift`); lazy persistence (unchanged close opens no second snapshot), failure-preserves-container-and-allows-close, flush-failure-vetoes; all panels via `AirframeSavePanel` with no sibling-append derivation and NSFileCoordinator publication to the granted URL; privacy-safe structured close logging (`ContainerError.diagnosticDescription`); durable commits via `F_FULLFSYNC`; per-document observers removed in `deinit`.

Cache: OS cache directory + no migration, corrupt/mismatched entries rejected on read (`DerivedDataCache.swift`, `CacheFileEnvelope.swift`); quota preference in exact 100 MB units 0–10 GB, defaults 2 GB iOS / 5 GB macOS, quota 0 disables and clears (`AirframeCachePreferences.swift`); `GraphPreparedSeriesCache` is the reference coalescing implementation (debounced per-shape tasks, playback suspension, idempotent shutdown); all RAM caches document-scoped `@State` released via `releaseDocumentCaches()`; reader-scan disk-cache version 3 (`ReaderScanDiskCache.swift:12`); no intra-process TOCTOU between quota check and write.

Security: offline parsers fully hardened — `ByteStream` bounds-checks every read, `VariableByteDecoder` caps at 5 bytes with 32-bit overflow rejection, `FieldPredictorApplier` uses checked arithmetic, `LogFileScanner`/`LogHeaderInterpreter` enforce comprehensive limits, `FrameStream` guarantees forward progress on corruption, no `try!`/`fatalError`/`precondition` in the parsing packages; `AirframeContainer` bounds/alignment/digest verified with checked-integer arithmetic; `.airframepreset` is plain JSON into a fixed schema with no zip/tar/gzip extraction anywhere (zip-slip class absent); container export rejects `..`/`.`/`/`/`\`/NUL with a double symlink check; MSP validates payload length + CRC before use, CLI encode rejects control bytes, no device/file string reaches a CLI command. No network/analytics/telemetry; App Sandbox enabled; security-scoped resources balanced.

## Recommended sequence

1. S1 (varint trap) — smallest change, highest reach.
2. C1 (table chunk write path) — largest recurring runtime cost and a clear invariant violation.
3. Stability trio (re-entrant close, zombie document, Cmd-Q flush) — data-loss / correctness under termination.
4. Remaining medium security (device path), cache reconcile/actor throughput, formatter caching + `LogDataView` memoization.
5. Priority-3 sweep as capacity allows.
