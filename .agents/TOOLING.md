# Tooling Knowledge Base

- When a command already runs with `Airframe/` as its working directory, use paths such as `App/Airframe.xcodeproj` and do not retain root-relative `Airframe/...` prefixes. For checks spanning both the public submodule and root `.agents/`, run from the workspace root instead. Mixing the two path bases caused repeated false “No such file or directory” diagnostics before otherwise valid builds.

- On the current Xcode 26.5 toolchain, `xcrun xctrace record --template 'SwiftUI' --attach <pid>` can create an incomplete trace that fails export with `Document Missing Template Error`. Do not interpret macOS `ps` state `SX` as proof that the app is suspended: `S` means sleeping and `X` means traced/debugged; a stopped process is indicated by `T`. Verify responsiveness and CPU/process state directly. Prefer the Time Profiler template for reliable CLI attachment and open the SwiftUI template interactively in Instruments when its specialized lanes are required.
- In zsh, invoke unified logging as `/usr/bin/log show` or `/usr/bin/log stream`; bare `log` resolves to the shell's arithmetic builtin and fails with `too many arguments`.
- `xcodebuild -target AirframeTests -derivedDataPath ...` is invalid because `-derivedDataPath` requires a scheme, test-products path, or xctestrun; a direct target build without it also built unnecessary universal package products here and failed to resolve the local `Logging` module. For focused app-hosted tests, temporarily enable `AirframeTests` in `App/AirframeTests/AirframeTests.xctestplan`, run the shared `AirframeTests` scheme with `-only-testing:AirframeTests/<Class>` and a temporary DerivedData path, then restore the test-plan flag immediately.
- **Mandatory before every `Airframe/` commit or amend:** obtain the user's changelog-relevance decision, add exactly one English `Changelog: <draft>` trailer when relevant, then verify it with `git -C Airframe show -s --format=%B HEAD`. Do not update the root submodule pointer until this check passes.
- `AirframeCache` diagnostics are visible in Xcode/Console under subsystem `com.kumkju.airframe` and category `airframe.cache`; filter on that category to inspect hits, misses, writes, evictions, quota changes, corruption, and clearing.
- **Mandatory new view/cache lifecycle gate:** identify the composition-root owner; list every captured log-data root and task; provide idempotent terminal shutdown; reject late store/register/publication; cancel queued and synchronous cooperative work; clear RAM/adapters; add focused shutdown/token-release tests; then repeat open/use/close in the live macOS app and require idle CPU, no later analysis/cache messages, zero pending writes, and zero live document/window/hosting/open-model/workspace/document-cache roots.
- Do not accept `leaks: 0`, falling RSS, an LRU byte limit, `onDisappear`, or deallocation of the `NSDocument` wrapper as standalone close proof. Reachable global closures, retained `NSWindow`/`NSHostingView` graphs, task handles, and allocator-reserved empty regions each require different evidence.
- Fire-and-forget persistence is not sufficient background isolation for large value snapshots: queued tasks retain every captured snapshot while a single actor serializes writes. Debounce before constructing the payload, keep only one pending task per stable dataset identity, suspend persistence during playback, and expose shutdown statistics in `airframe.cache` logs.
- For macOS document lifetime tests, inject a private `NotificationCenter` into global window registries, register a closure that captures a weakly observed token, post `NSWindow.willCloseNotification`, and assert both registry removal and token deallocation. This deterministically catches whole-document leaks without relying on noisy RSS measurements.
- A close tombstone keyed by `ObjectIdentifier` with a weak wrapper still accumulates dictionary keys and wrappers after windows deallocate. Use `NSHashTable<NSWindow>` with `.weakMemory` and `.objectPointerPersonality` for an identity barrier that neither retains windows nor grows one permanent record per close.
- Platform document wrappers may outlive their visible windows. Close-time memory correctness should be asserted on explicit shutdown state (zero source bytes, empty decoded maps/history, nil persistence/snapshot roots), while lifecycle logs report released logical bytes; RSS alone cannot identify which root survived.
- For post-close live acceptance, prefer `vmmap -summary <pid>` physical footprint plus targeted `heap --showSizes --addresses='<type>' <pid>` counts over `ps` RSS. Darwin RSS can remain above 1 GB when `vmmap` shows only about 146 MB of physical footprint because resident `MALLOC_SMALL (empty)`/`MALLOC_LARGE (empty)` allocator regions are reusable but not yet returned; treat live document-type counts and allocated bytes as the retention signal.
- When RSS rises specifically on close, inspect the close maintenance path before assuming a retained UI graph. Opening a fresh persistence actor can duplicate the complete document value, and unconditional full compaction can transiently allocate/copy every live blob. Test unchanged close with an injected compaction-preparation probe and unchanged file length.
- For a running macOS process, `heap -sortBySize <pid>` identifies live Swift/Foundation allocations; pipe it through `rg` for project types because unfiltered generic SwiftUI type names can produce hundreds of thousands of lines. Use `heap --addresses='<exact-class-prefix>' <pid>` (for example `heap --addresses=GraphCacheCoverageState <pid>`); the pattern cannot start with `*`, and `heap <pid> -instances <type>` is not valid syntax. Combine the resulting address with `leaks --trace=<address> --groupByType <pid>` for direct root paths, while `--traceTree` is useful for the wider reverse tree, even when conventional leak detection reports zero leaks. The direct trace can reveal a global Swift dictionary's item count and its closure path into document state.
- `heap` option order is strict: use `/usr/bin/heap --showSizes --addresses='<type>' <pid>`. Placing `-showSizes` after a space-separated `-addresses` pattern makes it part of the class pattern and fails with “cannot match the start of a class name.”
- For a closed-window leak, count both document wrappers and native roots. A process can have zero live `AirframeNSDocument` objects while retained `NSWindow -> NSHostingView` graphs still own all document caches; trace the hosting controller or an `AnalysisWorkspaceStore`, not only the document class.
- A unit test that calls `NSDocument.close()` directly does not cover the user path. Reproduce AppKit ordering with `window.performClose(nil)`, await `NSWindow.willCloseNotification`, weakly observe the hosting controller/view, and then await removal from `NSDocumentController.shared.documents`. This caught the asynchronous-close gap that the direct-close lifecycle test missed.
- SwiftUI `@Entry`/environment defaults can intentionally leave one small observable state object alive for the process lifetime. Before classifying it as a closed-document root, trace its address: `leaks --trace=<address> --groupByType <pid>` will identify a static `<Key>.defaultValue` root. Confirm separately that no large result arrays or source buffers hang from that default.
- Do not run macOS and iOS `xcodebuild` operations concurrently against the same default DerivedData directory; XCBuild shares `build.db` and one invocation fails with `database is locked`. Run them sequentially or assign distinct `-derivedDataPath` values.

- For analyses of several disjoint Blackbox ranges, do not replace indexed range reads with one large enclosing read when the gaps are substantial. `DecodedLog` supports independent streams, so concurrent indexed range reads reduce wall time while retaining exact full-rate samples. The real 89-second CHIRP log took about 40 seconds sequentially; parallel sweep reads reduced the complete standalone scan-plus-analysis run to about 26 seconds, with the already-open app avoiding the standalone scan portion.
- On macOS, avoid driving a segmented `Picker` and a split-view surface directly from the same computed binding when selection can replace the hierarchy during the current AppKit mouse event. Keep a local display selection, validate the persisted mode against the selected log's capabilities, and defer externally driven changes with a yielded task so AppKit finishes `mouseDown` before the split-view subtree changes.
- Coalescing an expensive task is insufficient when its completion is written only into SwiftUI surface-local `@State`: repeated surface replacement cancels every waiter, leaving a forever-resetting loading UI while the retained task runs. Keep the user-visible load state and completion delivery beside the coalesced task in a window-scoped observable store; make surface appearance an idempotent trigger only.

- The Airframe Xcode project is `Airframe/App/Airframe.xcodeproj`; run app builds/tests with `Airframe/App` as the working directory (not `Airframe/App/Airframe`). Continue redirecting simulator/app `xcodebuild` output to a log and inspect it only after completion.
- Create Airframe commit tags with `git -C Airframe tag ...`; running `git tag` from the wrapper root targets the private workspace repository and cannot resolve public-subrepo commit IDs.

- Release tooling treats `Changelog:` trailers as editorial input and never publishes them without review.
- Use the shared `Airframe Beta` scheme for tester and TestFlight archives. Its `Beta` configuration inherits `Release`, keeps the app and Swift packages release-optimized, and adds the app compilation condition `AIRFRAME_BETA`. The normal `Airframe` scheme archives with `Release` and must remain free of beta-only presentation.

- Xcode 26 may reserialize `project.pbxproj` comments and reorder/augment `Info.plist` while an otherwise read-only `xcodebuild` runs. After builds, inspect `git status` and reverse only the exact incidental diff before continuing; do not carry those unrelated rewrites into a feature change.

- Extract a numbered Betaflight `debugType_e` catalog directly from any local ref with the enum as the source of raw values:

  ```sh
  ref=2026.6.0-rc3
  git -C betaflight show "$ref":src/main/build/debug.h | awk '/^typedef enum \{/{inside=1; next} inside && /DEBUG_COUNT/{exit} inside { line=$0; sub(/^[[:space:]]*/, "", line); sub(/,.*/, "", line); if (line ~ /^DEBUG_/) { sub(/^DEBUG_/, "", line); print rawValue++, line } }'
  ```

  Compare the result with the designated names in `src/main/build/debug.c`; do not infer raw values by counting an Airframe array. Run this for each supported ref because insertions and removals change later integer meanings.
- In zsh, an unmatched unquoted glob aborts the command before `rg` runs (`no matches found`). Quote optional path patterns or pass only paths verified to exist when a reference checkout may omit a directory.
- For SwiftUI `fileExporter(item:)` with CoreTransferable `FileRepresentation`, add a constant non-empty `.suggestedFileName` on the representation even when the view supplies `defaultFilename`. Without it, macOS SwiftUI can pass an empty string to `NSFileWrapper.preferredFilename`; the dynamic closure overload triggers recursive generic-metadata resolution and `EXC_BAD_ACCESS` on the current toolchain. Add a test that evaluates `transferRepresentation`, because tests of prepared files alone do not execute this runtime path.
- App-hosted focused tests still compile the complete test target; every new test source must compile even when another suite is selected.
- Launch Services can cache an older exported UTI declaration. Verify the built app's `UTExportedTypeDeclarations` rather than `UTType.conforms(to:)` on a development machine after changing conformance.
- Swift `String` equality treats canonically equivalent Unicode forms as equal. Enforce persisted path normalization by comparing normalized and original UTF-8 bytes.
- New app/test sources need explicit file reference, build file, group child, and source-phase entries; only the `Packages` group is synchronized.
- Run Xcode builds/tests sequentially when they share DerivedData to avoid `build.db` locking and ambiguous logs.

- A pure `.borderless` AppKit `NSWindow` hosting SwiftUI through `NSHostingController` collapsed to an AX-reported `900 × 0`/invisible window in Airframe. For a visually borderless fixed SwiftUI window, use a technically `.titled` + `.fullSizeContentView` window, hide title/traffic-light controls, make the title bar transparent, then call `setContentSize` after assigning the hosting controller. Verify runtime window geometry through System Events, not only by compiling.
- Resolve validation paths relative to the command's explicit `workdir` exactly once. With `workdir` set to the public `Airframe/` submodule, package paths begin with `Packages/`, not `Airframe/Packages/`.
- With `workdir` inside a package such as `Airframe/Packages/AirframeCaptions`, a workspace-relative command like `git -C Airframe ...` cannot resolve. Run repository Git checks from the workspace root or use paths relative to the selected package.
- Validate `.xcstrings` catalogs as JSON with `jq empty`, not with `plutil -lint`; `plutil` reports valid String Catalog JSON as an unexpected leading `{`. On Xcode 26.5, `xcrun xcstringstool compile <catalog> --dry-run` also requires `--output-directory <tmp-dir>`.
- Xcode 26.5 ships `xcstringstool` at `$DEVELOPER_DIR/usr/bin/xcstringstool`; on machines with versioned Xcode app bundles, resolve it with `xcrun --find xcstringstool` before catalog compile dry runs instead of assuming `/Applications/Xcode.app`.
- When several simulator runtimes contain identically named devices, take destination IDs from the scheme's `xcodebuild` available-destinations error/listing. `xcrun simctl list devices available` can include devices from runtimes that the active Xcode project cannot target.

- In zsh, `status` is a read-only special parameter. When capturing an `xcodebuild` exit code before printing a log tail, use a task-specific name such as `build_result=$?` or `test_result=$?`.

- Do not run macOS and iOS `xcodebuild` commands concurrently against the same default DerivedData path: both contend for `XCBuildData/build.db` and one fails with “database is locked.” Run them sequentially or provide distinct `-derivedDataPath` values.
- If macOS `xcodebuild test` fails while signing `Airframe.app` with `code object is not signed at all` in the embedded `AirframeTests.xctest`, rerun with a fresh explicit `-derivedDataPath`. The default DerivedData product can retain a stale unsigned test bundle even when the same test succeeds in an isolated DerivedData path.
- For a fresh isolated DerivedData build, use `build_dir=$(mktemp -d /tmp/<task>.XXXXXX)` directly. Do not remove a fixed prior `/tmp` directory first; the command safety layer rejects `rm -rf` even when the target is narrow.

## General Rules

- When auditing several large context files, inspect line counts and headings first, then read files in bounded per-file chunks. One combined `sed` dump can be truncated and hide the exact duplication or contradiction being reviewed.

- The app source/test groups in `App/Airframe.xcodeproj` use explicit file references. Add new Swift files to both their group and target source build phase. The installed `xcodeproj` Ruby gem (`1.28.1` observed 2026-07-23) is safer than hand-authoring PBX object IDs.
- `FileDocumentWriteConfiguration` has no accessible public initializer. Focused document-format tests should call a small explicit serialization seam such as `packageFileWrapper()` rather than constructing `WriteConfiguration`.
- In zsh, `status` is a read-only special parameter. When preserving a command exit code around log inspection, use a task-specific name such as `test_exit_code=$?`.
- For macOS beachball diagnosis, build into an isolated DerivedData path, launch only that exact app binary, resolve its PID from the binary path, and capture `sample <pid> 5 -file <path>`. Two-document sampling can distinguish global-executor decode load from synchronous MainActor body churn without modifying the app; terminate only the isolated test PID afterward.
- SwiftUI `.disabled` and `.allowsHitTesting(false)` do not automatically suppress AppKit local `NSEvent` monitors or always-active tracking areas inside representables. Native scroll/pointer helpers must propagate `EnvironmentValues.isEnabled`, guard monitor callbacks, restore cursor/crosshair state when disabled, and return unhandled events unchanged.
- SwiftUI `.inspector` content is hosted separately from the modified content view and does not inherit an environment value applied only to that content. Pass document-scoped environment values explicitly inside the inspector closure.
- SwiftUI `.inspector` can adapt to overlay presentation on macOS at narrow widths. It has no public API for forcing a permanent side-by-side layout; keep the content's geometry self-contained when native inspector appearance takes priority.

- Prefer CLI-first workflows.
- Use Xcode itself only for special cases where CLI tools are insufficient.
- Use `rg` / `rg --files` for fast codebase search.
- Keep planning and durable context in `.agents/`, not in the upstream clone.
- Do not use GSD workflows, GSD skills, `.planning/`, or GSD-generated roadmap/backlog structures in this workspace. Use the project's own `.agents/` files instead.
- Do not modify `blackbox-log-viewer/` unless the user explicitly asks.
- Do not introduce external dependencies without the user's explicit approval.
- Keep all project artifacts in English, including code, variables, documentation, agent files, comments, and commit text, even if the chat is in German.
- Before writing or reviewing any file under `Airframe/`, official docs, commit messages, PR titles, or PR descriptions, make sure there is no AI/agent/Codex/ChatGPT attribution. Keep that context only in `.agents/`.
- Human-visible text should be clear developer prose, slightly casual when appropriate, and never stiff generated boilerplate.
- The workspace root is now its own private Git repo. Check `git rev-parse --show-toplevel` before commit-sensitive work because the root repo, `Airframe/`, `blackbox-log-viewer/`, and `betaflight/` are separate Git repositories linked by submodules.
- `betaflight-configurator/` is also a read-only reference submodule. Keep it detached at the pinned workspace commit and never commit or push inside it.
- Use `./scripts/ws-status.sh` from the root to inspect root and submodule working trees together.
- Use `./scripts/ws-pull.sh` from the root for routine synchronization. It fast-forwards the read-only upstream reference submodules and leaves any pointer changes visible for an explicit root commit. It intentionally does not initialize nested upstream submodules such as Betaflight's firmware dependency modules.
- Use `./scripts/ws-commit-root.sh "message"` for normal root workspace commits when submodule worktrees are clean. It stages only root-owned paths, agent entry points (`AGENTS.md`, `CLAUDE.md`), and submodule pointers.
- Git submodules check out commits, not branches. Before doing commit-bearing work inside `Airframe/`, run `git -C Airframe status -sb` or `git -C Airframe branch -vv` and switch to the intended branch first, usually `git -C Airframe switch master`. If a commit was created on detached HEAD but should simply become the new `master` tip, `git -C Airframe branch -f master <commit> && git -C Airframe switch master` reattaches it without rewriting the commit.

## Swift and Xcode

- A Swift method with a defaulted parameter, such as `runtimeStatus(options: Options = .init())`, does not satisfy a distinct parameterless protocol requirement `runtimeStatus()`. If the protocol also has a default implementation, existential calls silently dispatch to that default. Use a clearly named explicit bridge such as `captureRuntimeStatus()` and test through the protocol existential.
- For independent app build/test jobs, use a distinct explicit `-derivedDataPath` per job. This permits safe parallel iOS build, macOS build, and focused macOS tests without `build.db` contention. Redirect each complete command to its own log and inspect only after it exits.
- New app and app-test Swift files are not discovered automatically by this Xcode project. Register them in the appropriate group and target source phase with `xcodeproj`, then validate both platform builds because a successful SwiftPM test does not cover app target membership.
- Use separate iOS and macOS entitlement files when one Universal target needs macOS App Sandbox plus iCloud Key-Value Storage. Set normal `CODE_SIGN_ENTITLEMENTS` to the shared iOS file and use `CODE_SIGN_ENTITLEMENTS[sdk=macosx*]` for macOS.
- Verify a built app's effective signing with `codesign -d --entitlements :- /path/to/Airframe.app`; project settings alone do not prove the final signed payload.
- Before iOS simulator tests, inspect available devices with `xcrun simctl list devices available`; simulator names are machine-local and can drift from old commands.

- Use Swift 5.9 language mode unless the user explicitly approves a change.
- For Swift Packages, use `swift build` and `swift test` directly where possible.
- Use `xcodebuild` for package or app scheme builds/tests when required.
- Use `xcodeproj` for Xcode project file inspection or edits when appropriate.
- The `xcodeproj` gem does not know the `name` attribute of `PBXFileSystemSynchronizedRootGroup` and drops `name = Packages` on every save (it warns about it). After any scripted project edit, restore `name = Packages;` and the `/* Packages */` comments in `project.pbxproj`, or Xcode shows the group as `../Packages`.
- Use `xcrun simctl` for simulator lifecycle, app install/launch, screenshots, and log collection.
- For simulator-related `xcodebuild`, do not pipe output to `grep`.
- Instead, write useful log files, wait for `xcodebuild` to finish, and inspect the logs afterwards.
- Prefer modern Swift Testing for package tests.
- Folder/file open panels (`NSOpenPanel`, SwiftUI `.fileImporter`) cannot be driven by synthetic key events via AppleScript/`System Events`; Cmd+Shift+O and Cmd+Shift+G + path + Return did not reliably open/select a folder in the running app. To prove a load/decode parallelization without the UI, measure at the package level instead: a throwaway Swift Testing case that reads the real logs and times a serial `for` loop of scans vs a `withThrowingTaskGroup` fan-out (`reader.open` -> `decodedLog` -> `flightInfo()` per file) gives a concrete serial-vs-parallel ratio. Debug-build absolute times are inflated; use the ratio. Delete the temp test after capturing numbers.

## Current Tool Corrections Learned

- In zsh shell wrappers, do not assign to `status`; it is a read-only special parameter. Use a neutral name such as `result` for a command exit code.
- Swift Testing parameterized test methods cannot use `private` or `fileprivate` argument helper types unless the test method access is restricted the same way. Prefer internal test case helper structs for parameterized tests to keep test discovery straightforward.
- In this workspace, `swift test` with Swift Testing prints an XCTest compatibility summary with `Executed 0 tests` before the real Swift Testing run. Check the later Swift Testing summary; the initial XCTest line alone is not the result.
- With Xcode 26.5, use the new test-results subcommands for result bundles, e.g. `xcrun xcresulttool get test-results tests --path /tmp/result.xcresult --format json` and `xcrun xcresulttool get test-results test-details --path /tmp/result.xcresult --test-id 'Suite/testName()' --format json`. Passing the bundle path positionally or using old `--path` placement variants can fail.
- For Xcode Cloud failures, inspect both artifacts: `build-for-testing.xcresult` can report `status: succeeded` and zero errors while the actual failing XCTest assertions appear only in `Logs for ... test-without-building .../xcodebuild-test-without-building.log`.
- For Xcode Cloud `test-without-building.xcresult`, use `xcrun xcresulttool get test-results tests --path <bundle> --format json` plus `xcrun xcresulttool get object --legacy --path <bundle> --format json | jq '.actions._values[0].actionResult.issues'`. A macOS `build-for-testing.xcresult` may be green while the `test-without-building` bundle contains both package-test failures and host-launch errors.
- SwiftPM tests inside an Xcode test plan should not require source checkout paths at runtime. If a test must inspect a package resource such as `Localizable.xcstrings`, first try the `#filePath` source path, then fall back to the built package resource bundle such as `AirframeCaptions_AirframeCaptions.bundle`.
- Xcode Cloud macOS Debug/test hosts can fail to launch with `Could not launch “AirframeTests”`, RunningBoard error 5, and `Launchd job spawn failed` when app-hosted tests launch the sandboxed product. Airframe now avoids this by keeping app-hosted tests out of the Cloud test plan; do not reintroduce CI-only entitlement-patching scripts unless a new Cloud workflow explicitly requires them.
- The Swift project directory is `Airframe/`. Set the command working directory directly to package directories such as `Airframe/Packages/BlackboxCore` before running `swift test` or `swift build`.
- After renaming or moving a SwiftPM package directory, remove the package `.build/` directories before testing. Swift/Clang module cache files can retain the old absolute path and fail with `SwiftShims` module-cache path mismatches.
- When using `rg` patterns that contain Markdown backticks, wrap the whole pattern in single quotes. Unescaped backticks inside a double-quoted zsh argument trigger command substitution.
- SwiftPM `.process("Fixtures")` test resources may be available at the resource bundle root rather than under the original subdirectory. Fixture loaders should first try `subdirectory: "Fixtures"` and then fall back to a root lookup.
- For Swift ArgumentParser `ParsableArguments` used in `@OptionGroup`, avoid custom initializers on the parsable wrapper type unless they are proven compatible with completion generation. Keep the parsable options type internal and map it to a separate plain model type for service tests; this keeps `--generate-completion-script` / wrapper aliases such as `--completion bash` working.
- When a command type name would shadow Foundation types, such as a `data` subcommand, give the Swift type a different name like `DataCommand` and set `CommandConfiguration(commandName: "data")`.
- Airframe CLI `.bbfixture` files under test resources are a fixture DSL, not direct CLI input. They must be materialized by `CLIFixtureLoader` in tests; running `.build/debug/airframe info Tests/.../info-rich.bbfixture` directly fails with schema/header errors because the file is not a raw Blackbox log.
- Use root `Flightlogs/` for copied full private logs used by manual smoke/performance checks. Keep package test fixtures minimal and prepared under the package test target.
- Do not run `swift test` and `swift build` in parallel for the same package directory. SwiftPM serializes access to the shared `.build` directory with a lock, so the second command just waits. Run them sequentially when measuring package verification time or reading clean output.
- Do not run two `xcodebuild` commands in parallel against the same project and DerivedData location. Xcode can fail with `XCBuildData/build.db: database is locked`. Run them sequentially or give each command an isolated `-derivedDataPath`.
- When a SwiftPM package consumes a local path dependency and newly added source files in that dependency are not visible from the consuming package, remove the consuming package's `.build/` directory and rerun `swift test`. This occurred for `AirframeCLI` after adding new `BlackboxReader` source files.
- For local-only full-log smoke checks without adding repo files, create a temporary SwiftPM executable under `/tmp` that depends on the local package by absolute path, then run it against `Flightlogs/small/*`. This avoids putting private logs or smoke harnesses into package tests while still validating real log iteration.
- SwiftPM packages without explicit platform declarations may need `@available(macOS 10.15, iOS 13, tvOS 13, watchOS 6, *)` on public APIs that use `withTaskGroup`, even when async package tests run on a modern host.
- This local SwiftPM version does not support `swift package init --package-path`; create the target directory first and run `swift package init --type executable` with that directory as the working directory.
- When creating a temporary SwiftPM executable, make sure the shell actually `cd`s into the target directory before `swift package init`; setting a not-yet-existing directory as the command working directory fails, and running from `/tmp` initializes the package in `/tmp`.
- A temporary executable package that calls `BlackboxReader.summaries(in:)` needs the `@available(macOS 10.15, *)` annotation on the `@main` type, not only on `main()`.
- Superseded 2026-07-13: the workspace root is now a private Git repository with submodules. Run Airframe project commits inside `Airframe/`, root workspace commits in `/Users/daniel/Projekte/Airframe`, and never commit inside `blackbox-log-viewer/` or `betaflight/`.
- For `git diff` on Airframe project files, run the command from `/Users/daniel/Projekte/Blackbox/Airframe` with repo-relative paths such as `Packages/BlackboxReader/...`. Running `git diff -- Airframe/Packages/...` from the workspace root is outside the Airframe repository and fails like a no-index comparison.

# Xcode filesystem-synchronized package recognition

- A new Swift package created directly on disk under the filesystem-synchronized `Packages` root can remain cached by an already-open Xcode instance as a normal blue folder, even when `swift package describe` and `xcodebuild` resolve it correctly.
- Do not add a separate `XCLocalSwiftPackageReference`; the project intentionally discovers its local packages through the existing `PBXFileSystemSynchronizedRootGroup`.
- Reliable recovery: quit Xcode, move the project-specific DerivedData and workspace `UserInterfaceState.xcuserstate` to a recoverable temporary backup, move the new package's local `.swiftpm` data aside, atomically remove and reinsert the complete package directory, then reopen the project.
- A Git `intent-to-add` entry and reinserting the directory while Xcode remains open do not refresh this classification.

# Sandboxed document replacement

- An opened macOS document's security scope does not reliably permit creating hidden staging files beside it. For whole-document migration/replacement, obtain a same-volume staging directory with `FileManager.url(for: .itemReplacementDirectory, in: .userDomainMask, appropriateFor: sourceURL, create: true)`, build and validate there, then publish through `NSFileCoordinator` and `replaceItemAt`.
- An `NSSavePanel` grant authorizes the selected destination but does not reliably authorize the container writer's hidden sibling temporary file. For creation at a new destination, stage under a same-volume item-replacement directory appropriate for the destination's parent, validate, and coordinate a final move to the selected URL while both source and destination security scopes remain active.
- Registering two exported UTIs with the same `.airframe` extension can leave Launch Services returning a dynamic UTI even after later builds remove one declaration. For the single regular-file format, an early-installed `NSDocumentController` subclass that returns the canonical UTI for regular `.airframe` files makes native reopen deterministic across stale development registrations.
- Launch Services does not reliably change an existing exported UTI from `com.apple.package` to `public.data`, even across many rebuilt app registrations. Give a physically incompatible replacement format a new UTI identifier. For an Open panel that must also accept files created while the old identifier was active, use `allowedFileTypes` with the exact supported extensions plus an `NSOpenSavePanelDelegate` that disables legacy `.airframe` directories; a UTI-only filter will gray out files carrying stale metadata.

- To diagnose AppKit main-menu problems, observe `NSMenu.didAddItemNotification`/`didChangeItemNotification`/`didRemoveItemNotification` plus `didBeginTracking`/`didEndTracking` and log, per event, the menu title, whether it is the File/main menu, the delegate class, the affected item, and a full snapshot of the File menu's item titles. The snapshot diff between consecutive events names the exact items that flicker. `NSMenu.didHighlightItemNotification` does not exist as a Swift symbol; use `Notification.Name("NSMenuDidHighlightItemNotification")`. Stream with `/usr/bin/log stream --process <pid> --level debug --predicate 'eventMessage CONTAINS "[Claude-DEBUG]"'` — plain `log` hits a zsh builtin and fails with "too many arguments".
- Wrapping an existing `NSMenuDelegate` in a forwarding proxy (`forwardingTarget(for:)` plus a `responds(to:)` override, keeping a strong reference because `NSMenu.delegate` is unowned) reveals whether a menu mutation happens inside `menuNeedsUpdate` or out of band. For Airframe's File menu only the first wipe per menu session came from `menuNeedsUpdate`; the rest were SwiftUI command re-renders.
- In zsh, `status` is a read-only special parameter. When preserving an `xcodebuild` exit code before tailing its log, use a task-specific name such as `result_code=$?`; assigning `status=$?` reports `read-only variable: status` after the build and masks its successful exit status.
- In `App/`, plain `ruby` fails with "No version is set for command ruby" because `App/.tool-versions` pins ruby via asdf without a global default. Prefix structured project edits with `ASDF_RUBY_VERSION=4.0.6 ruby ...`; the `xcodeproj` gem is available in that version.
- Export an attach-based Time Profiler capture for scriptable comparison with `xcrun xctrace export --input <trace> --xpath '/trace-toc/run[@number="1"]/data/table[@schema="time-profile"]' --output <xml>`. Sum row weights for total CPU and filter the resolved thread `fmt` beginning with `Main Thread`; manual scrub captures can contain very different input-event counts, so use stack absence/presence and normalized behavior rather than raw scrub totals alone.

On 2026-08-05 it exposed `GraphPreparedSeriesCache.restoreIfNeeded` decoding a large binary property-list bundle for roughly 54 seconds, with substantial transient memory amplification.
- Package-backed reference-log UI state must never use `replaceLogSources` as its ordinary publication path: that method deliberately SHA-256-hashes each source and rebuilds descriptors. Profile stacks through `DocumentStateStore.notifyPackageChange` -> `ReferenceLogStore.notifyPackageChange` -> `replaceLogSources` identify this mistake immediately; publish state-only changes through metadata and reserve source replacement for attach/remove.
