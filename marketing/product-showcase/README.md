# Airframe Product Showcase

Reusable source material for presenting Airframe on Discord and, later, on the website.

## Contents

- `FEATURES.md`: prioritized feature list and editorial scope.
- `SCREENSHOTS.md`: capture list, scene setup, and filenames.
- `DISCORD.md`: ready-to-post copy in the intended sequence.

## Editorial Rules

- Lead with what the pilot learns or can do, not with implementation details.
- Prefer neutral, explanatory language over promotional language.
- Explain the purpose of each feature and the question it helps answer. Avoid telling the reader what to do unless an instruction is necessary.
- Use one image per Discord post. Use two only where comparison is the point.
- Keep every post understandable on its own; Discord provides no dependable layout relationship between text and image.
- Show real flight data, but remove personal filenames, paths, coordinates, controller identifiers, and other private information.
- The final Discord set consists of six macOS screenshots: Overview, Graph and Playback, Spectrum, Step Response, Flight Map, and Flight Controller Import.
- Capture one coherent visual set on the same macOS version, window size, appearance, accent color, and app build.
- Do not showcase incomplete, hidden, or known-problem behavior.
- State clearly that Airframe remains in active development and does not yet include every feature planned for 1.0.

## Recommended Publishing Order

1. The story behind Airframe
2. Overview
3. Graph and playback
4. Spectrum
5. Step Response
6. Flight Map beta
7. Flight Controller Import
8. Short closing post

Airframe document organization and the native/local/private details remain useful website text, but do not need dedicated posts or additional screenshots. The introduction and closing post reuse images from the six-image set.
